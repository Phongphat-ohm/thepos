# ADR 0001: Technology Stack and Architectural Foundations
## บันทึกการตัดสินใจทางสถาปัตยกรรม: ชุดเทคโนโลยีและรากฐานระบบ

- **สถานะ (Status)**: APPROVED
- **วันที่ (Date)**: 2026-11-16
- **ผู้มีอำนาจตัดสินใจ (Deciders)**: Software Architect, Tech Lead
- **บริบท (Context)**: ระบบ POS และจัดการเงินปันผลสหกรณ์ชุมชน สำหรับเครื่องหน้าร้าน 2–5 เครื่อง

---

## 1. บริบทและปัญหา (Context and Problem Statement)

ระบบต้องการแอปพลิเคชันหน้าร้านที่มีความรวดเร็วในการสแกนบาร์โค้ด มีการเชื่อมต่อกับฮาร์ดแวร์ใบเสร็จความร้อน ESC/POS และลิ้นชักเก็บเงินอย่างเสถียร ใช้ทรัพยากรเครื่องน้อย ทำงานบน Windows 10/11 ได้อย่างราบรื่น ในขณะที่ส่วนเซิร์ฟเวอร์ต้องรองรับการประมวลผลธุรกรรมทางการเงินที่มีความแม่นยำสูง ป้องกันการขายสินค้าแย่งสต็อก และไม่เกิดข้อผิดพลาดจากเลขทศนิยมลอยตัว (Floating-Point)

---

## 2. ทางเลือกที่ได้รับการพิจารณา (Considered Options)

1. **ฝั่ง Desktop Client**:
   - *Option A*: Electron + React
   - *Option B*: Tauri 2 + React + TypeScript *(เลือก Option B)*
   - *Option C*: C# / .NET WPF
2. **ฝั่ง Backend API**:
   - *Option A*: Node.js + Express
   - *Option B*: Bun + Hono *(เลือก Option B)*
   - *Option C*: Go + Gin
3. **ฝั่ง Database & ORM**:
   - *Option A*: MySQL + TypeORM
   - *Option B*: PostgreSQL 16 + Prisma ORM *(เลือก Option B)*

---

## 3. ผลการตัดสินใจและเหตุผล (Decision Outcome)

### 3.1 ฝั่ง Desktop: Tauri 2 + React + shadcn/ui
- **เหตุผล**:
  - Tauri 2 ใช้ WebView ประจำระบบปฏิบัติการและมีแกนหลักเป็น Rust ทำให้ใช้หน่วยความจำ (RAM) น้อยมาก (เฉลี่ย 40–80 MB เทียบกับ Electron ที่มักเกิน 300–500 MB) ซึ่งสำคัญมากสำหรับเครื่อง POS ที่มักมีสเปกปานกลาง
  - การควบคุมฮาร์ดแวร์เครื่องพิมพ์ใบเสร็จและลิ้นชักเก็บเงินผ่านคำสั่งเนทีฟของ Rust ทำได้อย่างเสถียร รวดเร็ว และปลอดภัย
  - React + shadcn/ui + Tailwind CSS ให้ความยืดหยุ่นสูงสุดในการออกแบบหน้าจอขายแบบ Light Mode ภาษาไทยที่คมชัดและตอบสนองคีย์บอร์ดอย่างฉับไว

### 3.2 ฝั่ง Backend: Bun + Hono
- **เหตุผล**:
  - Bun ให้ประสิทธิภาพความเร็วสูงในการรัน TypeScript โดยไม่ต้องผ่านกระบวนการ Transpilation แยกต่างหาก ช่วยลดเวลาใน CI/CD และการพัฒนา
  - Hono มีขนาดเล็กมาก (Lightweight), ทำงานร่วมกับ Bun ได้อย่างไร้รอยต่อ, มีระบบ Middleware ที่ทรงพลัง และรองรับ RPC-style Type safety ร่วมกับ `@thepos/contracts`

### 3.3 ฝั่ง Database: PostgreSQL 16 + Prisma ORM
- **เหตุผล**:
  - PostgreSQL มีความทนทานต่อข้อมูลการเงินระดับสูง รองรับ ACID เต็มรูปแบบ และมีคำสั่ง `SELECT ... FOR UPDATE` สำหรับการล็อกแถวในระดับฐานข้อมูลขณะตัดสต็อกสินค้า ป้องกันการเกิด Race Condition
  - Prisma ORM 6.x มีการตรวจสอบ Type Safety ที่เข้มงวด ช่วยป้องกันข้อผิดพลาดในการเขียน Query และรองรับชนิดข้อมูล `Decimal` โดยตรง ป้องกันปัญหา Floating-Point

---

## 4. ผลกระทบและการประเมินความเสี่ยง (Consequences & Risk Mitigation)

- **ความเสี่ยง**: พนักงานและผู้พัฒนาอาจคุ้นเคยกับ Node.js มากกว่า Bun
  - *การจัดการ*: สถาปัตยกรรมถูกเขียนด้วย TypeScript มาตรฐาน และใช้คำสั่งผ่าน Bun Workspaces ที่มีความเข้ากันได้สูงกับ ecosystem ของ Node
- **ความเสี่ยง**: การพิมพ์ภาษาไทยบนเครื่องพิมพ์ความร้อน ESC/POS อาจมีปัญหาสระลอยหรือการตัดคำ
  - *การจัดการ*: ออกแบบ Hardware Adapter ใน Rust ให้จัดการการแปลงรหัสอักขระ (TIS-620 / UTF-8 ESC/POS) หรือเรนเดอร์เป็นภาพบิตแมปความละเอียดสูงก่อนส่งเข้าเครื่องพิมพ์
