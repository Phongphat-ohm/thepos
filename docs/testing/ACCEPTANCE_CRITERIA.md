# ACCEPTANCE CRITERIA BY PHASE
## เกณฑ์การตรวจรับงานของแต่ละเฟสการพัฒนา

ก่อนจะถือว่าเฟสใดๆ พัฒนาเสร็จสิ้น (Status: COMPLETED) จะต้องผ่านเกณฑ์การตรวจรับด้านล่างนี้อย่างครบถ้วน โดยมีหลักฐานการทดสอบยืนยัน

---

## เกณฑ์มาตรฐานทั่วไปสำหรับทุกเฟส (General Quality Gates)
1. โค้ดคอมไพล์ผ่านสมบูรณ์ ปราศจากข้อผิดพลาดของ TypeScript (`tsc --noEmit` = 0 errors)
2. ชุดการทดสอบอัตโนมัติประจำเฟสทำงานผ่าน 100%
3. ไม่มีการใช้ Mock Data หรือ Hardcoded responses ใน Production Workflow
4. ข้อความแจ้งเตือนและส่วนติดต่อผู้ใช้เป็นภาษาไทยที่ถูกต้องและเข้าใจง่าย
5. ได้รับการบันทึกรายงานผลใน `docs/roadmap/PHASE_STATUS.md`
6. ฟอร์มและการยืนยันใช้ Modal หรือ SweetAlert2 ร่วมตามหน้าที่ของขั้นตอน และงานที่ต้องรอแสดง spinner แผงความคืบหน้า หรือ skeleton ตรวจว่าการซ้อนหน้าต่างและการคืนโฟกัสทำงานด้วยคีย์บอร์ด

---

## เกณฑ์การตรวจรับเฉพาะรายเฟส (Phase-Specific Criteria)

### Phase 1: Foundation and Authentication
- [ ] ติดตั้ง Bun Workspace Monorepo เรียบร้อย โครงสร้างแพ็กเกจเป็นไปตามเอกสาร
- [ ] Prisma Migration รันผ่าน และสร้างตาราง Users, Roles, Devices, Sessions ได้สำเร็จ
- [ ] ผู้ใช้สามารถเข้าสู่ระบบด้วย Username/Password และสามารถปลดล็อกหน้าจอด้วย PIN
- [ ] ระบบมี Setup Wizard สำหรับกำหนดค่าเซิร์ฟเวอร์และลงทะเบียนร้านค้าครั้งแรก

### Phase 2: Products and Inventory
- [x] เพิ่ม/แก้ไข สินค้า พร้อมกำหนดราคาขายทั่วไป และราคาสมาชิกได้ถูกต้อง
- [x] รองรับสินค้าที่มีหลายบาร์โค้ด และสินค้าไม่มีบาร์โค้ด
- [x] ระบบแปลงหน่วยนับ (เช่น ลัง -> กล่อง -> ชิ้น) คำนวณสต็อกอย่างแม่นยำ
- [x] รับสินค้าเข้าคลังตามล็อต (FEFO/FIFO) บันทึกวันหมดอายุและต้นทุนจริง
- [x] นำเข้าไฟล์สินค้าจาก Excel/CSV ได้โดยไม่เกิดความเสียหายต่อข้อมูลเดิม

### Phase 3: Core POS and Payments
- [ ] หน้าจอ POS ทำงานด้วยปุ่มลัดแป้นพิมพ์ (F2–F10, Ctrl+N, Esc) ได้อย่างราบรื่น
- [ ] ยิงบาร์โค้ดเพิ่มสินค้าเข้าตะกร้าได้อย่างต่อเนื่อง
- [ ] พักบิลและเปิดได้หลายบิลพร้อมกันโดยไม่สับสน
- [ ] ตัดสต็อกสินค้าตามล็อตจริงแบบ FEFO/FIFO และบันทึกต้นทุนประวัติศาสตร์ (COGS)
- [ ] ชำระเงินสด (คำนวณเงินทอนถูกต้อง), บันทึกสลิปโอน และแยกชำระได้
- [ ] สั่งพิมพ์ใบเสร็จความร้อน ESC/POS ภาษาไทย และสั่งเตะลิ้นชักเก็บเงินได้
- [ ] ระบบรับคืนสินค้าอ้างอิงบิลเดิม โดยไม่สามารถคืนเกินจำนวนที่ซื้อจริงได้

### Phase 4: Membership and Shares
- [x] ค้นหาสมาชิกด้วยบัตรบาร์โค้ดหรือเบอร์โทรศัพท์ และปรับราคาสินค้าเป็นราคาสมาชิกทันที
- [x] บันทึกยอดซื้อสะสมของสมาชิกลงสมุดบัญชีซื้อ (Purchase Ledger) อัตโนมัติเมื่อจบการขาย
- [x] จัดการบัญชีหุ้นสมาชิก บันทึกเพิ่ม/ลด/โอนหุ้น และมีประวัติตรวจสอบย้อนหลังได้ 100%

### Phase 5: Dividends and Purchase Rebates
- [x] สร้างและจัดการงวดบัญชีสหกรณ์ได้
- [x] แยกการคำนวณเงินปันผลตามหุ้น และเงินเฉลี่ยคืนตามยอดซื้อตามสูตรที่กำหนด
- [x] มีระบบ Preview ตรวจสอบยอดเงินปันผลรายสมาชิกก่อนอนุมัติ
- [x] เมื่องวดบัญชีถูกล็อก (`APPROVED_LOCKED`) ข้อมูลผลลัพธ์จะไม่สามารถแก้ไขได้
- [x] บันทึกการจ่ายเงินปันผล (เงินสด/โอน) และติดตามยอดเงินคงค้างของสมาชิกได้ถูกต้อง

### Phase 6: Dashboard, Reports, and Shifts
- [x] แคชเชียร์เปิดกะและบันทึกเงินทอนเริ่มต้นได้
- [x] ปิดกะและนับเงินสดจริง เปรียบเทียบกับยอดคำนวณในระบบ แสดงเงินขาด/เกินถูกต้อง
- [x] แดชบอร์ดสรุปยอดขายและสินค้าใกล้หมดอายุแสดงผลได้ตามสิทธิ์
- [x] รายงานกำไรขั้นต้นคำนวณจากต้นทุนของล็อตที่ถูกขายจริง
- [x] ส่งออกรายงานเป็นไฟล์ Excel (.xlsx) และ PDF ภาษาไทยที่อ่านง่ายและสวยงาม

### Phase 7: Settings, Backup, and Deployment
- [x] ตั้งค่าหัว/ท้ายใบเสร็จ และทดสอบฮาร์ดแวร์หน้าร้านได้ ตรวจการตั้งค่า สแกน และคำสั่งพิมพ์ ตัดกระดาษ และเปิดลิ้นชักผ่าน Playwright และ Rust ตามขอบเขตการตรวจรับที่ผู้ใช้ระบุ การตอบสนองของอุปกรณ์จริงอยู่นอกผล Playwright
- [x] สคริปต์สำรองข้อมูลอัตโนมัติพร้อมเข้ารหัส GPG ทำงานได้ตามกำหนดเวลา
- [x] ทดสอบสคริปต์กู้คืนฐานข้อมูล (`restore.sh`) บนสภาพแวดล้อมจำลองสำเร็จ 100%
- [x] Docker Compose สำหรับระบบ Production (Caddy + Bun + PostgreSQL) บิลด์และรันผ่าน

### Phase 8: Security, Performance, and UAT
- [x] ทดสอบจำลอง 5 เครื่องขายพร้อมกัน ไม่มีปัญหาแย่งสต็อกหรือสต็อกติดลบ
- [x] ทดสอบ 10,000 บิล กระทบยอดเงินปันผลตรงกัน 100% (ผลต่าง 0.00 บาท)
- [x] ความเร็วค้นหาสินค้า P95 < 300 ms (`47.49 ms`), ความเร็วยืนยันบิล P95 < 2 วินาที (`498.3 ms`)
- [x] ตรวจประเมินความปลอดภัย OWASP และตรวจรับระบบตามแผน Phase 8 แล้ว (บันทึกข้อค้นพบเปิดค้าง Medium 2, Low 1 ใน `SECURITY_AUDIT.md` เพื่อติดตามแก้ไข)
