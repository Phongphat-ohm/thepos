# TEST STRATEGY & QUALITY ASSURANCE PLAN
## แผนกลยุทธ์การทดสอบและการประกันคุณภาพซอฟต์แวร์

---

## 1. ลำดับชั้นการทดสอบ (Testing Pyramid & Tooling)

| ระดับการทดสอบ | เครื่องมือที่เลือกใช้ | ขอบเขตการทดสอบ |
|---|---|---|
| **Unit Testing** | [Vitest](https://vitest.dev/) | - ฟังก์ชันคำนวณ Decimal (ปันผล, เฉลี่ยคืน, ภาษี, ส่วนลด)<br>- การแปลงหน่วยนับ (Unit conversions)<br>- สัญญา Zod Validation Schemas ใน `@thepos/contracts` |
| **API Integration Testing** | Vitest + Hono Test Client + Testcontainers / Postgres | - ทดสอบ Endpoint ของ Hono API ทุกตัว<br>- ทดสอบการตรวจสอบสิทธิ์ RBAC Middleware<br>- ทดสอบ Transaction และ Foreign Key Constraints |
| **Concurrency Testing** | Vitest (Parallel Workers) + Postgres | - จำลองเครื่องแคชเชียร์ 5 เครื่องยิงขายสินค้าชิ้นสุดท้ายพร้อมกัน (Race Condition)<br>- ตรวจสอบว่าไม่มีสินค้าติดลบ และไม่เกิด Deadlock |
| **End-to-End (E2E) Testing** | [Playwright](https://playwright.dev/) / WebDriver | - ทดสอบขั้นตอนการขายตั้งแต่ต้นจนจบ (เปิดกะ -> สแกนสินค้า -> เลือกสมาชิก -> คิดเงิน -> พิมพ์ใบเสร็จ -> ปิดกะ) |
| **Financial Reconciliation Testing** | Automated Custom Runner | - รันจำลองบิล 10,000 รายการ แล้วนำเข้าเอนจินปันผล ตรวจสอบผลรวมเงินบาทและเศษสตางค์ไม่ให้มีความคลาดเคลื่อน (0.00 THB Variance) |
| **Disaster Recovery Testing** | Shell Script (`restore.sh`) | - ดัมป์ข้อมูลจากฐานข้อมูลจริง -> เข้ารหัส GPG -> ล้างฐานข้อมูลทดสอบ -> กู้คืนและเทียบ Hash ข้อมูล |

## 2. กรณีทดสอบวิกฤต (Critical Test Cases)

### 2.1 TC-CONCURRENCY-01: การแย่งซื้อสินค้าชิ้นสุดท้าย (Last Unit Race Condition)
- **เงื่อนไข**: สินค้า A มีสต็อกคงเหลือ 1 ชิ้นในล็อต L1
- **การทดสอบ**: ส่งคำขอ Checkout สินค้า A จำนวน 1 ชิ้นพร้อมกันจาก 2 POS Clients
- **ผลลัพธ์ที่ถูกต้อง**: คำขอแรกต้องผ่านการบันทึกสำเร็จ (201 Created) ส่วนคำขอที่สองต้องได้รับข้อความปฏิเสธ "สินค้าคงเหลือไม่เพียงพอ" (409 Conflict หรือ 400 Bad Request) สต็อกคงเหลือสุดท้ายต้องเป็น 0 พอดี (ห้ามติดลบเด็ดขาด)

### 2.2 TC-FINANCE-01: ความแม่นยำของเงินปันผลและการปัดเศษ (Dividend Satang Reconciliation)
- **เงื่อนไข**: สมาชิก 100 คน มียอดหุ้นและยอดซื้อที่แตกต่างกัน คำนวณเงินปันผลและเงินเฉลี่ยคืน
- **การทดสอบ**: รวมยอดเงินปันผลรายคน และเทียบกับยอดรวมภาระผูกพันในระดับระบบ
- **ผลลัพธ์ที่ถูกต้อง**: ผลรวมของเงินปันผลรายบุคคลจะต้องเท่ากับยอดรวมที่คำนวณได้ในระดับกองทุนปันผลพอดี (Tolerance = 0.00 บาท)

### 2.3 TC-IDEMPOTENCY-01: การส่งคำขอชำระเงินซ้ำเนื่องจากเครือข่ายหลุด (Network Retry)
- **เงื่อนไข**: แคชเชียร์กดชำระเงิน แต่เน็ตหน้าร้านกระตุก ทำให้ POS ส่งคำขอเดิมพร้อม `idempotency_key` ซ้ำ
- **การทดสอบ**: ยิงคำขอชำระเงินซ้ำ 3 ครั้งติดต่อกันด้วยคีย์เดียวกัน
- **ผลลัพธ์ที่ถูกต้อง**: เซิร์ฟเวอร์ต้องประมวลผลตัดสต็อกและบันทึกบิลเพียงครั้งเดียว และคืนค่าผลลัพธ์ของบิลเดิมทั้ง 3 ครั้ง สต็อกถูกหักเพียงครั้งเดียว
